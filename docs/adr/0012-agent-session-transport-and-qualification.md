# ADR 0012: Agent session transport and qualification

- **Status:** accepted
- **Date:** 2026-11-01
- **Source:** change `claude-acp-chat-session` design D1, D4, D5, D10, D11, D13 and D15; user decision (2026-10-31), argv profiles with no bundled adapter; ADR 0001, ADR 0002 and ADR 0004

## Context

ADR 0004 places runtime adapters in the host and allows capabilities only from evidence for the adapter version in use. Agent sessions need a transport that does not let a streamed reply or history replay delay Stop, permission replies or close. The execution ledger and workspace cleanup gate (ADR 0001) must still identify one session's process tree. Later runtimes must follow the same contract, not infer it from an archived change.

The user installs Node (at least version 22 for the Claude adapter) and the adapter. Kumiko does not bundle an adapter or manage provider sign-in. Automated fake-agent tests prove Kumiko's behaviour, not the behaviour of any real adapter version.

## Decision

1. **One contained adapter process per session.** Start through `UnitManager.launch(kind: 'agent', target: <workspace path>)`. The existing ledger, unit cap, cleanup gate and settlement apply. Closing a session terminates its contained unit, including tool descendants; a crash affects that session only. Do not use the adapter's multi-session process support.
2. **Transcript data and control are separate.** Reserve one host-to-desktop data channel per start or Continue (ADR 0002). After `agent/attach`, send normalized newline-delimited JSON events: `user`, `agentText`, `thought`, `tool`, `toolUpdate`, `plan`, `notice`, `replay{start|end}` and `turn{stopReason}`. State (`agent/state`), permission requests and resolutions, Stop results, turn end, exit and close failure travel on channel 0. The host is the sole state writer; each state publication increments a per-live-session sequence, and the desktop ignores stale sequences. Turn end and idle are published only after the turn's transcript events are enqueued, not necessarily delivered: control may arrive before trailing data, whose display order remains the event channel's order. Control is never queued behind data, so transcript backpressure cannot consume the pending-control allowance or delay other sessions' control.
3. **The host owns the ACP boundary.** Runtime-profile and agent methods are additive desktop-host protocol methods, gated on `Capability.agent`, with no protocol version bump. The contract comprises `runtime/list`, `runtime/save`, `runtime/remove`, `runtime/setDefault`, and `agent/start`, `agent/continue`, `agent/attach`, `agent/prompt`, `agent/stop`, `agent/permissionReply`, `agent/close`, `agent/release`, `agent/records`. Start answers after native session creation; Continue answers after initialization and availability checks, returning `mode: load|resume` before restoration begins at attach. Both return the event channel and normalized adapter/capability information. Prompt acknowledges acceptance rather than turn completion; Stop acknowledges immediately, and close acknowledges entry into `closing`, with their asynchronous outcomes on control. Release frees the exited session's channel; records reads at most 128 saved references without launching a process. Do not tunnel raw ACP to the desktop.
4. **Runtime profiles are argv, not shell commands.** Profiles reuse the shell-profile argument and environment validators, add `runtimeKind`, omit `cwd`, and always execute in the session's target workspace. There is no bundled adapter.
   - Use absolute executable paths as supplied, with file/executability checks; resolve bare names on the host's `PATH`, then the well-known directories below. Refuse relative paths containing directory separators, and skip empty or relative search directories: never resolve an executable against the target checkout. Missing files are `executable-not-found`; POSIX files without `access(X_OK)` or Windows non-`.exe` files are `not-executable`, with the requested or first matching path named.
   - On Windows, try the `PATHEXT` extensions in order. The first match must be an `.exe`; refuse `.cmd` or `.bat` with the batch-file reason and do not continue to a later `.exe`. Refuse absolute `.cmd` and `.bat` paths too.
   - Search macOS `/opt/homebrew/bin`, `/usr/local/bin`; Linux `/usr/local/bin`, `~/.local/bin`; both POSIX systems `~/.npm-global/bin`, `~/.volta/bin` and the newest `~/.nvm/versions/node/*/bin`; Windows `%APPDATA%\npm`, `%ProgramFiles%\nodejs`. These follow `PATH`, including when a GUI launcher supplies a minimal environment.
   - Detect the installed `claude-agent-acp` shim in a worker isolate at host start, with one overall two-second cap including startup and filesystem lookups; terminate the worker on completion, error or timeout. Detection only inspects files: it neither launches Node nor installs anything or verifies Node's version (Node 22+ remains a user prerequisite). Resolve its package script (`lib/node_modules/@agentclientprotocol/claude-agent-acp/dist/index.js` below the POSIX install root, following the bin symlink; `node_modules\@agentclientprotocol\claude-agent-acp\dist\index.js` beside the Windows shim). Require the script to exist. Find `node` / `node.exe` beside the shim first, then on the search path. The built-in read-only, memory-only profile uses absolute Node plus absolute script, prepending Node's directory to its own `PATH` override.
   - A POSIX user profile may use `npx -y @agentclientprotocol/claude-agent-acp@<version>`. On Windows use `node.exe <nodejs dir>\node_modules\npm\bin\npx-cli.js -y @agentclientprotocol/claude-agent-acp@<version>` instead of the batch shim.
5. **Qualified capabilities are exact-version data.** `packages/host/lib/src/agent/qualified_adapters.dart` contains exact `(adapterName, version)` pairs with their qualified extra capabilities (`load`, `resume`). A run must both advertise a capability in `initialize` and match that exact list entry to claim it. An adapter that completes ACP protocol 1 initialization gets only the safe baseline without such evidence: prompt, streaming, tool activity, permission requests and cancel. A missing version is unqualified. Other protocol versions are refused.
6. **Qualification evidence survives the change.** Real per-version, per-OS observations live in `docs/qualification/claude-agent-acp.md`. `tool/qualify_claude_acp.dart` and the user record real runs: launch, streaming, tool activity, permission request, Stop, close with confirmation, load, resume, the observed authentication-required code and message, and macOS Finder/Dock detection and launch. The fenced document template is not evidence. No list entry is added before its evidence exists.
7. **CI checks the claims on every OS.** `tool/check_qualification.dart` parses the qualified source and evidence. Every listed pair needs baseline, authentication and macOS Finder/Dock evidence; load and resume are required only when claimed. Checked items must pass on Windows; only user-verified Linux/macOS items may be `unproven`. Authentication `pass` requires the observed code and message. Missing evidence, checked failures, blank results, unknown items/OSes and duplicate sections fail with pair/OS/item diagnostics. Unclaimed load/resume failures or `unproven` do not block other claims. A missing or unparseable qualified source fails. An empty list prints **NO CLAIMS (no adapter qualified)** with exit 0, never ACCEPTED or QUALIFIED. Nonempty claims print **ACCEPTED** while allowed unproven items remain (listing each), and **QUALIFIED** only when every checked item passes. Unproven is never counted as passed; M1 close requires QUALIFIED.

## Runtime profile implementation

`RuntimeProfileDefinition` in `domain` shares the shell-profile field validators and encoded-size bounds without introducing a working-directory field. Store v5 persists user profiles and native session references; built-ins remain in host memory. Profile deletion does not cascade into saved native records.

`RuntimeProfileService` owns `runtime/*` and `default_runtime`. A missing stored default remains selected but unavailable, with `defaultReason`; detection never silently replaces that choice. Only an unset default may select the first available profile, with the detected built-in ordered before user profiles. Detection has one overall two-second deadline and runs outside the host event loop. `ExecutableResolver` preserves Windows first-match refusal and uses the shared native `access(X_OK)` helper on POSIX. Detected profiles do not capture the inherited `PATH` in their bounded wire or persisted fields. For Claude Code profiles whose resolved executable is Node, shared start/Continue launch preparation puts that executable's directory first on the complete inherited `PATH`; editable copies retain this behavior. Explicit profile environment overrides apply last, including case-insensitive Windows `PATH` overrides. Preparation and overrides affect only the launched unit, never the host's process environment.

## ACP client and turn implementation

Both POSIX process-backed stdin and Windows pipe stdin observe leader exit independently of native I/O completion. Exit fails pending and queued writes and releases an in-flight stdin close, including an SDK flush that never completes or a Windows descendant holding an inherited read end without consuming input. On Windows the worker retains its native handle until `WriteFile` returns; endpoint disposal still joins the actual writer after containment termination, rather than closing a handle underneath blocked I/O. The existing 1 MiB caller queue and chunking bounds are unchanged. Pipe cwd checks compare native directory identities, since Windows logical junction paths can differ from their canonical paths without changing the working directory.

Start and Continue perform executable discovery and prechecks off the host isolate, including absolute-path checks, PATH entries and well-known runtime directories. A host-scoped launch resolver admits at most four probes with a five-second deadline and no waiting queue. Saturation or timeout reports `busy` before reserving a channel or spawning an adapter; timed-out probes retain their slots until the filesystem call returns. First-match, Windows batch refusal and POSIX executable checks are unchanged. Other live sessions' permission replies, Stop and close remain responsive while a probe is blocked.

`AcpClient` speaks ACP v1 over contained standard I/O. Its shared `LargeLinePermit` serializes parsing and normalization of lines larger than 1 MiB, with a 16 MiB line ceiling. Normalization finishes before the permit is released; the separate consumption callback then applies event-queue backpressure. Closing or failing a client also releases its permit or cancels its wait without waiting for native I/O disposal. The service still owns containment termination and pipe cleanup.

Native JSON-RPC string request IDs are admitted only up to 4 KiB of encoded JSON string contents, counting UTF-8 and escaping but excluding the surrounding quotes. Oversized IDs fail the session as `adapter-protocol` before permission callbacks or asynchronous ownership; they are never truncated or acknowledged as selected. Accepted string and integer IDs are preserved exactly for selected and cancelled replies. With at most 16 pending permissions, retained native ID contents are bounded to 64 KiB encoded per session.

Initialization admits adapter name and version only up to 4 KiB each of encoded JSON string contents, including UTF-8 and escaping. Oversized identity is refused as `adapter-protocol` before qualification, record creation, or any start/Continue response can retain or interpolate it; identifiers are rejected, not silently shortened.

An explicit permission reply must pass the bounded native stdin queue admission before the pending choice is removed or `selected` is published. Saturation returns `busy` and preserves the request for retry after stdin drains. A reply accepted into the queue still observes native-write completion and fails the session on actual I/O failure; the control acknowledgement never waits for the adapter to read.

Stop likewise admits all pending permission cancellations followed by `session/cancel` as one bounded stdin batch before changing Stop state, consuming choices or starting its deadline. If that complete batch cannot fit, the RPC returns `busy` with the prior turn/permission state intact, and Stop can be retried after stdin drains. No message is partially admitted and local saturation is not treated as adapter failure; accepted native-write failures still use the ordinary failed-session cleanup.

`AgentSession` owns the state sequence, pending permission choices and Stop outcome. Prompt acceptance does not await the native turn result. Stop queues cancelled permission outcomes before `session/cancel`, never kills the process, and retains `stopping` after an unconfirmed deadline until the one permitted late result. Native errors retain their code and message. The authentication classifier matches only the observed code `-32000` and exact message `Authentication required`, recorded for `@agentclientprotocol/claude-agent-acp` 0.99.1 on Windows and personally confirmed by the user. The scripted ACP fixture is test support, not qualification evidence, and reports only explicitly selected environment values.

Turn-end and Stop-result display messages and stop reasons are bounded to 4 KiB of encoded JSON string content, including escaping. A recoverable oversized native error therefore cannot exceed the control-message limit or prevent the transition back to idle. Exact authentication matching uses the original native error; the separate native diagnostic retains its UTF-8 limit and explicit truncation flag.

All native request-error dispatch performs exact authentication classification synchronously, bounds the retained native message to 4 KiB UTF-8, and drops arbitrary native `error.data` before completing the request future. Startup and restoration cleanup, as well as credit-blocked turn handling, retain only that bounded exception. Diagnostics preserve the original truncation flag so shortened authentication-like messages cannot become exact evidence; restoration failures visibly mark truncated text. Completed turns do not retain a separate native-error snapshot.

Successful prompt dispatch likewise validates and reduces the complete native result before completing its future, discarding unrelated result fields. The retained `AcpPromptResult` contains only bounded stop-reason display text, original exact cancellation classification, and truncation metadata. A credit-blocked completion retains this bounded result; canonical turn events preserve their truncation marker.

## Host agent service implementation

`AgentService` owns each live adapter unit, its reserved event channel and the private session record. Start validates the workspace and runtime before spawning, initializes ACP and creates the native session before inserting a record. Failures settle the process tree and release the channel without recording an incomplete session. Adapter stderr stays in a bounded memory ring; it is never written to the host log.

The successful native `session/new` response synchronously inserts its complete saved reference and binds the session's normalization and bounded relay callbacks before ACP dispatch advances to another input line. Initial messages, plans and tool updates coalesced with that response therefore have an owner before consumption, independent of pipe chunking; there is no unbounded pre-session event buffer.

Native session IDs are validated during response dispatch before the creation callback, saved record or request future takes ownership: at most 4 KiB of encoded JSON string contents, including UTF-8 and escaping. Oversized IDs fail `adapter-protocol` without truncation or record creation. Accepted IDs remain exact and usable by prompt, cancel, load and resume; unrelated native creation-result metadata is discarded before future completion.

Attach publishes the current sequenced state after the acknowledgement. The bounded event relay pauses adapter output instead of dropping events; Stop, permission replies and close remain on the control channel. Closing acknowledges entry into `closing` before cancellation, grace and containment settlement. A confirmed close retains the immutable native record but releases the live unit. Desktop or host loss uses the existing ledger reconciliation path, including adapter descendants.

An initial attach remains valid during unexpected-failure settlement until its original attach deadline, preserving the pending diagnostic and accepted transcript. Expiry records consumer abandonment and closes the relay even while another path owns settlement; settlement completion then releases the reservation, and late attach is refused. Explicit close still refuses an initial attach. Complete ACP stdout EOF independently fails the session and starts containment settlement even when the adapter leader remains alive; real leader exit still drains accepted ACP output before sealing its final count.

Unknown native errors retain their code and message in ordinary start/prompt results. Start errors and `agent/turnEnded` carry `nativeCode`, a `nativeMessage` bounded to 4 KiB UTF-8, and `nativeMessageTruncated` when shortened. Qualification rejects truncated diagnostics and waits for the actual prompt result, not its acceptance acknowledgement. An isolated session that starts successfully offers a separately approved minimal model request; a successful model turn is not authentication-failure evidence. Native authentication classification uses the real error recorded in `docs/qualification/claude-agent-acp.md`: an isolated `session/new` succeeded, then `session/prompt` returned code `-32000` and exact message `Authentication required`. The user confirmed both the authentication semantics and the saved evidence; synthetic errors test the classifier but do not establish that match.

Unexpected exit publishes Failed state as soon as the native leader's exit is observed, even while expanded final output is blocked on bounded relay admission. After ACP and accepted local event enqueues settle, the relay seals its final record count without clearing queued data. `agent/exited.eventCount` is a required nonnegative integer for that run's event channel. The desktop counts consumed decoded records and releases the failed session only after consuming that count; Continue and New session remain disabled until release completes. Explicit dismissal may discard pending data. Premature event-stream termination is a visible stream failure, not a successful drain. `ChannelWriter.closed` lets the service relinquish an abandoned channel even when all its bytes already flushed.

A close failure relinquishes the live transport but does not confirm process termination. The desktop retains the saved identity and error, shows a failed, termination-unconfirmed pane, disables Send, Stop and pending permission answers, and permits dismissal without sending close again to a forgotten session. Continue or a fresh session still passes through the durable workspace cleanup gate; unresolved cleanup is never presented as success.

For a new start whose session ID is not yet bound, the desktop retains early close-failure notifications in a per-host map bounded by the channel cap, only while starts are pending. Matching the start response consumes its failure before attaching, preserving the saved record and termination-unconfirmed recovery state instead of reviving forgotten transport. Unmatched notifications are cleared when pending starts finish or the host changes.

An initial `agent/attach` refusal with `unknown-session` is authoritative evidence that the host no longer owns the transport, including when attachment expired while the desktop was paused before binding its start result. The desktop retires the local live link and keeps its saved identity and failure diagnostic. Continue/New session and local dismissal remain available; it sends no redundant close or release to that forgotten owner.

An explicit close received during unexpected-failure settlement records dismissal intent and abandons the pending transcript relay, releasing credit-blocked local enqueues without starting duplicate containment cleanup. Confirmed settlement then reports `closed`; unresolved settlement still reports `closeFailed`, never a fabricated successful exit. Without explicit dismissal, the accepted transcript still drains losslessly.

Leader exit alone does not establish containment settlement: a surviving descendant can retain inherited native pipe handles. Unresolved cleanup therefore retains native I/O ownership until host exit. After shared shutdown, I/O disposal is joined only when the containment ID is absent from both the live-unit map and the durable ledger; confirmed settlement still disposes pipes normally.

## Continue and saved-record implementation

The desktop reserves the saved session's notification ownership before awaiting Continue. A failed exit received before its response is bound remains terminal: a zero-event exit releases without attaching, while accepted final events attach only for draining and retain the failure diagnostic. Binding cannot revive the ended transport or erase its release ownership. Recovery waits for release; dismissal of an already-ended pending Continue sends no redundant close.

`agent/records` reads the immutable native references without launching an adapter. Start target capture, saved-record and Continue checks, and `UnitManager`'s pre-spawn target recheck share the same bounded off-isolate workspace resolver: four slots, a five-second timeout, and no synchronous filesystem fallback on the host isolate. A timed-out resolver retains its slot until its native call returns; saturation reports busy rather than queuing interactive requests. Unit admission rechecks shutdown and reconciliation after resolution, before committing a pending row. Continue checks the recorded target's identity and cleanup gate before resolving a profile or spawning, and reserves a pending record synchronously so simultaneous requests cannot create two owners. If its original profile was removed, it uses the current default without rewriting the saved row.

The captured canonical path and identity are launch-admission conditions in `UnitManager`, not post-spawn checks. A mismatch is refused before any pending row or native process: Start reports `workspace-unavailable`, while Continue retains `resume-unavailable{target-changed}` and its saved reference. A missing or timed-out target at this final check uses the same agent-facing contract as the initial checks: `workspace-unavailable` for Start, `resume-unavailable{target-missing}` for Continue. Busy and shutdown errors keep their own classifications. Holding executable resolution cannot permit startup in a replacement or unavailable target discovered by that final check.

The adapter initialized by the Continue run determines availability. A qualified, advertised load takes precedence over resume; neither path sends a prompt or falls back to `session/new`. Restoration starts only after attach and uses the ordinary bounded event relay. Load brackets the ordered history with replay markers; resume emits the earlier-messages-not-shown notice. Both deadlines count 60 active seconds, excluding bounded event-consumption pauses.

A restoration failure retains `resume-unavailable` as its outer diagnostic and preserves the native subreason. An `auth-required` subreason enables native sign-in guidance and Retry; Retry uses Continue for that same saved conversation, never a replacement `session/new`.

Only the test-host extension accepts candidate qualification overrides. The release entry point ignores that environment and refuses test fixtures. The production qualified list names `@agentclientprotocol/claude-agent-acp` 0.99.1 for load and resume from the confirmed Windows observations; Linux/macOS user items remain explicitly unproven, so the qualification verdict is provisional ACCEPTED, not QUALIFIED.

## Native load regressions

The host qualification tests run real contained fixture processes and native pipes. They measure control acknowledgements beside saturated and stalled sessions, verify lossless delivery after backpressure, exercise deferred permissions and the Stop deadline at a full queue, reject a 17 MiB line, and gate two concurrent 8 MiB lines to observe permit ownership and handoff before desktop delivery.

RSS sampling uses asynchronous, single-flight OS queries so measurement does not block the desktop connection's credit loop. The scripted fixture serializes complete output lines, including gated and chunked lines, while keeping request handling concurrent. It reports permission responses when incoming messages are dispatched, not when asynchronous action continuations resume, so coalesced permission responses and cancellation requests retain their observed wire order. These regressions prove Kumiko's transport behavior on the OS running them; they do not qualify a real adapter version.

Automated fixture starts explicitly select their scripted runtime profile or isolate detection; an installed real adapter must not become a fixture's default runtime. Native desktop agent integration tests bind `KUMIKO_HOST` to the bundled test host because their ACP runtime uses `--test-fixture`; the other native integration tests retain the release host.

The ledger identity-failure fixture waits for explicit fault release before killing its leader. The test first observes all three process reports, then releases failure and verifies containment cleanup. Process startup speed is not assumed from a fixed one-second delay.

The native agent harness settles focused text input before dispatching the real application-exit request, avoiding the observed disposed-listener failure during Flutter's snapshot-based asynchronous exit dispatch. Reopen verification still exercises application shutdown, immutable layout restoration, no automatic agent launch, and explicit history loading.

## Desktop chat implementation

Only the ordered event channel appends canonical user/reply/turn/notice transcript records. Priority turn-end control updates action and authentication metadata without synthesizing duplicate or out-of-order transcript entries. Native sign-in guidance is rendered outside the transcript, and Retry resends the original prompt without replacing an unsent draft.

A split tab aggregates all contained agent statuses using explicit priority: Waiting for approval, Failed, Stopped or unknown, Stopping, Closing, Running, Starting, Idle, Saved/not running, Ended. An earlier idle pane cannot hide active or failed work in another pane, and status updates do not activate the tab.

`AgentController` owns live pane links and the bounded, in-memory transcript. Control notifications determine state and permission choices; the event channel determines transcript order. Accepted user prompts enter history only through the host's canonical event, so local draft submission cannot duplicate a prompt or reorder it ahead of earlier channel data. Identical prompts in different turns remain distinct.

Sparse tool updates preserve absent fields and their loss markers. Canonical tool events carry independent `contentTruncated` and `locationsTruncated` flags, with `truncated` as their aggregate; the encoded-byte budget includes all flags. Replacement content refreshes only content loss and `omittedItems`, while replacement locations refresh only location loss. A complete content replacement cannot conceal retained incomplete locations, nor can a location-only update erase retained content loss. Status-only updates preserve both, and the aggregate indicator clears only after every retained incomplete field has been completely replaced.

Prompt submission checks the 256 KiB UTF-8 text bound before entering the sending state. `Connection.request` also admits the actual JSON-encoded envelope, including escaping, before taking pending-request ownership; an envelope over the 1 MiB control bound is refused locally as `invalid-params`. Refused submissions preserve the draft, create no user/turn transcript records, and release the sending latch so a corrected prompt can be sent on the same live connection.

Native prompt admission is separate from desktop control admission. `AcpClient` admits the actual serialized native request before taking pending-request ownership, and `AgentSession` commits Running state and canonical user history only afterward. Saturated native stdin returns `busy` with the session still idle, no user/turn records and the desktop draft intact; retry after draining sends that draft once. Acceptance still does not wait for native write completion or the model result.

An admitted native write failure is a transport failure for every ACP method, including a prompt whose response arrived before its write acknowledgement. `AcpClient` closes the failed transport and fails its remaining requests; the session becomes Failed, containment is settled, and its immutable saved reference remains available for Continue. It is never published as a normal turn error followed by a falsely usable Idle state. This does not change synchronous local `busy` refusals or ordinary ACP remote prompt errors.

Chat panes persist only `sessionId` and `runtimeName`. Restore reads saved records without launching an adapter; Continue is explicit. Pane moves preserve live links and pending permission choices. Host loss disables runtime actions until the new host resolves saved records. Transcript eviction leaves a visible marker rather than persisting conversation text.

The generic `ViewCloser` contract replaces the terminal-only close branch. Agent and terminal panes share one mixed-tab confirmation while retaining their own settlement behavior. The workspace-bound Claude Code launcher uses runtime profile selection and the editor's argv-only configuration; missing capability, profile or workspace remains visible instead of selecting a fallback.

An outstanding prompt submission also requires close confirmation: the host may already have accepted it before the acknowledgement or sequenced Running state arrives. This conservative close policy does not change the displayed status. Cancel preserves the pane and sends no close or Stop; a rejected submission releases the sending latch and restores idle-close behavior.

## Protocol implementation

`host_protocol` owns the runtime/agent control DTOs and `AgentEvent` codec. Events are UTF-8 newline-delimited JSON; use `encodeAgentEvent` to apply encoded-size bounds, and one `AgentEventDecoder` per received channel. Register the inbound channel before sending `agent/attach`, and grant its initial credit only after attach succeeds. Existing reservation and credit primitives provide the handshake without another transport abstraction.

`RpcException.data.reason` remains the outer protocol error reason. Continuation failures carry their separate subreason as `resumeReason`. Permission display fields are clamped within the 64 KiB encoded notification bound without changing opaque option identifiers. Metadata that cannot fit even after display clamping is refused as `invalid-params`; the host must surface unusable adapter input as a visible session failure, not silently drop or automatically answer the request.

Qualification drives the ordinary agent service through the test-host extension with one exact candidate adapter/version override. This exercises Continue without pre-populating the production qualified list. The release entry point has no extension and cannot receive that override; only recorded passes may update the production list.

## Rejected alternatives

- **Share one adapter process per runtime profile.** Sessions share a process tree, so close cannot terminate just one session's tools; a crash ends every session and the ledger target no longer names one workspace (ADR 0001).
- **Send transcript events as control notifications.** There is no per-session control credit. A chatty session or large replay could exhaust the 4 MiB pending-control bound, lose the peer and delay unrelated sessions and terminals.
- **Tunnel raw ACP to the desktop.** This creates a second ACP client and prevents the host from resolving permissions on close or desktop loss; adapters belong in the host (ADR 0004).
- **Execute Windows batch shims through `cmd.exe /d /s /c`.** Arbitrary argv cannot be quoted safely through that boundary (the BatBadBut class); the existing shell-profile contract is argv only.
- **Qualify semver ranges.** Adapter load/resume behaviour can change within a minor release. A range would claim unobserved behaviour (ADR 0004 decision 2).
- **Run the real adapter in CI, or substitute a fake to qualify it.** Real runs require provider sign-in or an API key and spend tokens. Fakes only prove Kumiko's protocol and state-machine handling.
- **Leave these decisions only in the change design.** Later runtime adapters need the same durable transport and qualification contract.

## Consequences

- Each live session consumes its own contained process unit and event channel. Transcript backpressure remains local while control stays responsive.
- Users maintain their adapter and Node installation; detection and editable profiles expose unavailable executables rather than silently substituting another launch path.
- Accepting this ADR accepts the implemented contract, not cross-platform adapter qualification. Capability claims and evidence evolve together. An empty qualified list makes no qualification claim; the current 0.99.1 load/resume claims have confirmed Windows evidence and provisional ACCEPTED status while Linux/macOS user observations remain unproven. They cannot close M1 until every checked item passes and the checker reports QUALIFIED.
- The checker is an offline audit of recorded evidence and source, not a provider call or a substitute for the real qualification run.

## Reversal cost

Medium for process sharing (agent service and ledger kinds) and the normalized event/control contract (both desktop and host). Low for argv resolution, exact-version host data and the qualification record/checker. Writing this ADR has low reversal cost; replacing its transport contract later needs a superseding ADR.
